一个**离线可用的单文件物理知识库网页**，外加一条**自动校验流水线**。

## 三、核心机制：把「物理正确性」变成可自动判定的东西

项目真正值钱的部分不是内容，而是**判定机制**。

生成物理内容时最容易犯两类错误，而且这两类错误「看起来最像对的」：

1. **公式抄错** —— 把 ½at² 写成 at²、把 L/g 写成 g/L
2. **规律说反** —— 「摆长越长周期越短」

人工一条条核不现实。但放进机器里，它们反而能被**完全自动地判死**。

流水线一共六类检查：

| 检查 | 抓什么错 | 关键点 |
|---|---|---|
| **量纲一致性** | 公式写反、漏项、多乘一项 | 7 个基本量的指数组合必须完全一致 |
| **单位标注** | 公式对但单位标错 | 每个符号标注的单位必须与推导出的量纲相符 |
| **数值代入** | 量纲对但系数错（★ 最隐蔽的一类） | 代入自洽情境，与独立算出的参考值比对 |
| **变化方向** | 单调性反了 | 参数变化时结果的变化方向必须符合物理规律 |
| **跨公式一致** | 两条公式中有一条错了 | 同一情境下两条推导路径不同的公式必须给出同一答案 |
| **极端参数扫描** | 定义域问题 | 参数在很大范围内连续取值，不允许出现异常、NaN、无穷 |

另外还有一条**不等式关系**检查，以及项目特有的**「常见错误实测」**。

生成成品之后，还有一层独立的**质检**（`qc.py`），它查的是校验器管不到的东西——
因为校验器本身是可以被改的，**「再跑一遍校验」等于没质检**。质检共七项：指纹、
覆盖门槛、独立复算、成品一致性、质量扫描、内容自洽性、人工抽样单。

### 3.1 为什么必须多种手段并用（这是本项目最有说服力的发现）

量纲检查看起来很强大，但它有一个致命盲区：**量纲对，公式照样可以是错的。**

本项目实际抓到的例子（全部量纲正确、量纲检查无能为力）：

- `x = v₀t + at²`（漏 ½）
- `v² = v₀² + ax`（漏系数 2）
- `h = g·t²`（自由落体同样漏 ½）
- `a = v / t`（加速度定义漏掉初速度）
- `a = F_push / m`（牛顿第二定律忘减摩擦力）
- `f = μF_N` 用来算**静**摩擦力（静摩擦根本不能用这条公式）
- `F_x = F·sinθ`（cos 和 sin 记反）
- `F = F_x + F_y`（把矢量当标量直接相加）
- `F_AB = F_BA`（作用力与反作用力漏掉负号）
- `v = 2λf`（波速关系凭空多一个系数 2）

**在实测抓住的 66 条错误里，量纲检查只解决其中一部分。
其余的必须靠数值代入、变化方向、不等式关系。**
这不是巧合，而是必须配置多层校验的直接证据。

### 3.2 常见错误实测：证明校验收器真的在工作

知识库里每条「常见错误」都声称「会被某一类检查抓住」。这句话本身可能是假的。

所以流水线做了一件比较狠的事：**把每条错误写法原样当成一条公式，真的跑一遍那类检查，看它是不是真的被判为不通过。**

- 判为不通过 → 声称成立，标记「已实测 · XX 抓住」
- 判为通过 → **这条防线是假的**，流水线直接拒绝出成品

结果是 83 条常见错误里，**66 条被实测证实抓住**，另外 17 条**明确标注为「人工审核」**——
它们属于概念性错误（例如「重的物体下落更快」），不体现为公式写错，任何公式类检查都碰不到。

**主动标出自己的射程边界，比假装什么都能查更可靠。**

### 3.3 一份公式，只写一遍

公式在源文件里只存一串机器可读文本（如 `x = v_0*t + a*t^2/2`）。网页上显示的样子和校验器验算的东西，都是从这一串文本现场生成的——

- 校验用得着：解析成表达式树 → 量纲 / 数值 / 方向检查
- 网页显示用：同一棵表达式树 → MathML 数学排版

**所以不可能出现「网页上是对的、机器查的是另一个式子」这种漂移。**

### 3.4 ★ 一次真实的自我修补：我们漏掉了正文公式

这一节记录的是一件**真实发生过的事**，也是本项目最值得拿出来讲的一段。

验收成品时发现，正文里的公式写成了 `T = 2pi sqrt(L/g)`、`x = A cos(omega t + phi)`
——教材上从来不这么写。顺着这条线索排查，牵出了流水线的一个**真实盲区**：

> **正文散文里的公式，不参与任何校验。**
> 校验器只比每条公式的 `expr` 字段和符号表本身；定义、物理意义、推导、
> 例题里随手写下的式子，它一概不看。

后果是：某个知识点的定义正文写 `v = lambda f`，而**同一张卡片**的符号表
却把波长定义成 `wavelength` —— 同一个物理量在一张卡片里有俩名字。
**六道检查，一道都没抓到。**

处理分两步，缺一不可：

1. **发现盲区 → 变成检查。** 新增第七道检查「**内容自洽性**」：
   正文里用到的量，本知识点的符号表里必须找得到。符号名拿英文单词充数
   （`wavelength`）判硬问题直接拦；推导时顺手引用邻近知识点的量（θ、ω）
   列为软提示交人判断。
2. **修掉检查器自己暴露出来的缺陷。** 把符号名统一成 `lambda` 之后，
   独立复算立刻报 3 处 `invalid syntax` —— `lambda` 是 Python 保留字，
   而独立复算器**刻意**使用与生产端完全不同的代码路径（原生 `ast`），
   在语法层就把它拒了，**等于整批漏掉了含这个符号的公式**。
   这不是内容的错，是质检工具自己的洞，已修（求值前改名、取名字时还原）。
3. 同时把正文的公式做了排版还原：`2pi sqrt(L/g)` → `2π √(L/g)`、
   `F_合 = m a` → `F_合 = m a`、`A^2` → `A²`。全库 174 处、313 个片段，
   现在正文里的机器写法残留为 **0**。

这件事说明两点：

- **流水线的射程是可以被扩展的** —— 发现盲区 → 变成检查 → 这类问题永远不再犯；
- **「检查通过」不等于「没问题」** —— 所以才有第七项「人工抽样单」那一层，
  它必须由人用物理判断力去看，机器替不了。

> 内容由 AI 批量生成。为保证生成内容的物理正确性，设计并实现了一条
> **自动校验流水线**，涵盖量纲一致性、单位标注、数值代入、单调方向、
> 跨公式互证、极端参数扫描六类检查，未通过的内容自动丢弃、不入库。

> **独立复算**（用另一套代码重算 145 项，防止参考值被凑）、以及
> **「常见错误实测」**——把每条典型错误写法当作公式重新跑一遍检查，
> 验证它确实会被拦截：66/66 条可自动判定的错误全部实测通过，
> 其余 17 条概念性错误被明确标注为需人工审核。
>
> 成品为单文件离线网页（444.7 KB，零外部依赖，MathML 原生数学排版），
> 双击即开、断网可用、手机能开。

**这一句话同时说明了工程能力（流水线、自动化、自动化验证自己的验证器、
并且发现并修补了流水线自身的盲区）和物理素养（知道该查什么、知道量纲什么时候不管用）
——这是纯套壳项目给不了的。**

## 七、已知限制（主动写出来）

- 目前只覆盖力学，电磁学部分未开始
- 「人工审核」的 17 条概念性错误，流水线只负责把它们挑出来并标明，不负责判定
- 校验参数（情境数值、参考值）由生成方提供，如果情境参数本身选得不合适，可能掩盖错误。
  流水线对此有兜底：如果一条错误写法在**所有**情境下都「对得上」，会报「该防线实际上是空的」
- 内容自洽性检查有 4 条**软提示**（推导里引用了邻近知识点的 θ、ω、a_c），
  已列出但不拦截 —— 这类引用在教学中常见且合理，只是补进符号表会更完整
- 页面中「人工审核」条目的存在，说明本项目没有把「自动检查通过」等同于「内容一定没问题」
