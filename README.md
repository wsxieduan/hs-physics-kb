## 一、这个项目真正想解决什么

生成物理内容最容易犯两类错误，而它们**看起来最像对的**：

1. **公式抄错** —— 把 ½at² 写成 at²、把 L/g 写成 g/L
2. **规律说反** —— 「摆长越长，周期越短」

人一条条核不现实。但放进机器里，它们反而能被**完全自动地判死**。

所以这个项目的重点**不是内容本身**（高中物理的知识点网上到处都是），
而是**判定机制**：怎么把「物理上对不对」变成「代码可以自动判定的东西」。

---

## 二、六类自动检查

每一条公式都要经过这六类检查，全部通过才允许进成品：

| 检查 | 抓什么 | 例 |
|---|---|---|
| **量纲一致性** | 等式两边的基本量指数必须完全一致 | 抓「写反、漏项、多乘一项」 |
| **单位标注** | 每个符号标注的单位要和公式推导出的量纲相符 | 抓「公式没错但单位标错」 |
| **数值代入** | 给一组自洽的情境参数，算出的数必须等于独立算出的参考值 | 抓「量纲完全正确但系数写错」 |
| **变化方向** | 某参数增大时，结果该变大还是变小 | 抓「规律说反」 |
| **跨公式互证** | 同一情境下，两条不同公式算同一个量，结果必须相同 | 抓「两条公式各错一半却互相印证」 |
| **极端参数扫描** | 参数在大范围连续取值，全程不许出现异常、NaN 或无穷 | 抓「定义域问题」 |

举一个**只有数值代入才能抓住**的例子：

> 斜面问题里把 cos 和 sin 记反，写成 `F_x = F·sinθ`。
> 两边量纲完全一致（都是「纯数乘一个力」，结果还是 N），**量纲检查一点用都没有**。
> 只有代入 θ≈36.87° 才算得出 6 N，而正确值是 8 N —— 两个分量正好互换了。

## 三、除了校验，还有一层「质检」——查的是校验器管不到的东西

自动检查全绿 **不等于内容正确**。所以还有一层质检 `qc.py`，专门假设「成品有问题」：

| 环节 | 它在问什么 |
|---|---|
| **指纹** | 校验器源码有没有被偷偷改过？（放松检查比写错内容更危险） |
| **覆盖门槛** | 内容有没有被真正考过？（每个知识点至少 2 项数值代入、1 项极值扫描、1 项跨公式互证、1 条"量纲抓不到"的陷阱） |
| **独立复算** | 参考值是不是被"凑"出来的？—— 换一套**完全不同的代码**（Python 原生 `ast`）把每个数值重算一遍 |
| **成品一致性** | 网页里的内容，和源文件是不是同一份？ |
| **质量扫描** | 有没有占位符、空字段 |
| **内容自洽性** | 正文里随手写的符号，本卡片符号表里有没有？ |

其中**独立复算**是最关键的一条：如果有人把公式写错、再把「参考值」也改成错误公式算出来的数，
那么校验器会认为一切正常 —— 因为它比的就是这两者。**换一套代码重算，是唯一能发现这种情况的自动手段。**

## 四、目录结构

```
work/
  physkit/            校验器内核（纯标准库，零依赖）
    quantity.py       物理量与量纲代数（7 个基本量的指数组合）

  qc.py               质检器（查校验器管不到的东西）
  build_site.py       出成品：单文件 HTML
  prose_math.py       排版还原：机器写法 → 教材写法
  orchestrator.py     协作编排：AI 生产 → 代码质检 → 不合格打回重做
outputs/
  高中物理知识库.html    成品（单文件，断网可用）
  校验报告.md           校验底账：逐条记录每个公式经受了什么检查
  质检报告.md           质检结论
  项目说明.md           一页纸项目说明
```

## 五、怎么用

无需安装任何第三方库，只需要 Python 3。

```bash
# 1. 校验全部内容（结构 + 六类物理检查）
python work/validate.py

# 2. 出成品网页
python work/build_site.py

# 3. 质检（指纹 / 覆盖门槛 / 独立复算 / 成品一致性 / …）
python work/qc.py --check
```

`validate.py` 支持传入目录参数，方便只校验某一部分：

```bash
python work/validate.py work/kb
```

## 六、一条公式长什么样

知识库是结构化的 JSON，一条公式带的不只是公式本身，还有它的**适用条件**和**检查清单**：

```json
{
  "name": "洛伦兹力大小",
  "expr": "F = abs(q)*v*B*sin(theta)",
  "when": "带电粒子以任意非相对论速度进入匀强磁场，theta 为速度与磁场夹角",
  "checks": [
    { "type": "numeric",     "scenario": "斜入磁场", "expr": "abs(q)*v*B*sin(theta)", "ref": 0.0018 },
    { "type": "direction",   "scenario": "斜入磁场", "var": "theta", "lo": 0, "hi": 1.5707963267948966,
      "expr": "abs(q)*v*B*sin(theta)", "expect": "up" },
    { "type": "compare",     "scenario": "斜入磁场", "expr": "abs(q)*v*B*sin(theta)",
      "op": "<", "vs": "abs(q)*v*B" },
    { "type": "scan",        "scenario": "斜入磁场", "var": "theta", "lo": 0, "hi": 3.141592653589793 }
  ]
}
```

**同一条公式的显示、校验、排版都来自这一个来源**，不会出现「网页上是这个式子、机器验的是另一个」的漂移。

## 七、两个刻意的设计取舍

**① 显示与校验解耦。**
符号名是给机器用的（`v_avg` 能进表达式、能查表），但人看到的应该是教材写法（**v̄**）。
所以数据里一个字不改，只在「渲染成 HTML」的那一刻翻译。
好处：加显示规则**不可能影响任何校验结论** —— 改前改后校验项数一模一样。

**② 学会说"这条我判不了"。**
概念性错误（比如「重的物体下落更快」）不体现为公式写错，硬凑一个能跑的检查上去只会制造假安心。
这类一律标注「**人工审核**」—— 256 条常见错误里有 54 条是这么标的，**宁可承认边界，也不假装全覆盖**。

---

## 八、已知限制

- **自动检查覆盖的是"能被公式表达的错误"。** 表述是否地道、例子是否恰当，机器判不了。
- **数值比较存在量级下限。** 校验器的数值容差在量级小于 1 时按绝对误差 1e-6 处理，
  所以近代物理里 10⁻¹⁹ 量级的量（光子能量等）需要用合适单位（eV）或显式声明容差来写。
- **本仓库是"对外展示版"**：只包含内容、流水线与成品；
  日常协作的过程记录、运行时状态不在此仓库内。
